# AGENTS.md

Guidance for AI coding agents working on **oercat**, a static, bilingual (DE/EN) catalogue of
Open Educational Resources on AI & data literacy. See `README.md` for the user-facing overview.

## Pipeline at a glance

```
data/AiDaLi_OER_Katalog.xlsx          (single source of truth, DALIA metadata schema)
  → oercat/  (Python 3.13)            read → normalize → validate → export
  → site/data/oers.json + vocab.json  (generated, git-ignored)
  → site/    (Hugo)                   search page, /<lang>/oer/<No>/ pages, /<lang>/index.json
  → site/assets/js/search.js          client-side search + filters (MiniSearch, no framework)
```

| Module                | Role                                                                     |
|-----------------------|--------------------------------------------------------------------------|
| `oercat/schema.py`    | Column definitions (`COLUMNS`), sidebar facets (`FACETS`). Start here.   |
| `oercat/reader.py`    | Loads the `OER_Catalogue` and `Picklists` sheets with openpyxl.          |
| `oercat/normalize.py` | Pure per-cell parsers, registered in `PARSERS` by `Column.kind`.         |
| `oercat/validate.py`  | Runs parsers per row, collects `Issue`s, skips broken/duplicate rows.    |
| `oercat/export.py`    | Merges spelling variants, builds labels/facets, writes the JSON files.   |
| `oercat/cli.py`       | `validate`, `build-data`, `serve`, `build`, `fetch-vocab` subcommands.   |
| `oercat/vocab/`       | `aliases.yaml` (misspellings), `labels.yaml` (DE/EN display labels), `disciplines.json` (generated by `fetch-vocab`). |

## Commands

Use `uv` for everything; it also installs Hugo into `.venv` (pinned in `uv.lock`).

```bash
uv sync                          # install deps (incl. Hugo)
uv run pytest                    # tests (fast, no network)
uv run ruff check .              # lint (line length 100)
uv run oercat validate           # check the xlsx; prints a per-row report
uv run oercat build-data         # regenerate site/data/*.json only
uv run oercat build              # full static build into site/public/
uv run oercat serve              # live preview on :1313 (binds 0.0.0.0)
```

Before you finish a change, run `uv run pytest`, `uv run ruff check .`, and `uv run oercat build`
(the last one catches Hugo template errors).

## Rules and conventions

### Data
- **Don't edit `data/*.xlsx` unless asked.** Curators maintain it in Excel. Writing it with
  openpyxl can drop formatting and data validation. Fix bad input through
  `oercat/vocab/aliases.yaml` or the parsers instead.
- The `No` column is the permanent page URL (`/de/oer/<No>/`). Never renumber or reuse IDs.
- Don't edit anything that is generated: `site/data/*.json`, `site/public/`, `site/resources/`,
  and `oercat/vocab/disciplines.json` (refresh that with `uv run oercat fetch-vocab`).

### Python
- **Parsers never raise.** Every parser in `normalize.py` has the signature
  `parse(raw, ctx) -> value`. It reports problems with `ctx.warn(...)`, which keeps the row and
  drops the value. Extra output such as ORCID links or a derived year goes into `ctx.extra`.
  One bad cell must never stop the build.
- Errors (the row is skipped) are only for a missing required value, a duplicate `No`, or a
  shifted row. Everything else is a warning.
- Multi-value cells are separated by ` * ` (`schema.MULTI_SEPARATOR`). Use `split_multi`.
- Picklist matching ignores case and punctuation (`fold`). Only add an entry to
  `aliases.yaml` when the variant really is a different word.
- Style: small module-level functions, dataclasses, type hints, short docstrings. Use
  `# fmt: skip` for deliberately compact literals. `ruff format` isn't enforced repo-wide, so
  don't reformat files you aren't otherwise changing.

### Adding or changing a column / filter
1. Add a `Column(...)` to `COLUMNS` in `oercat/schema.py`. Add a `kind` and a parser in
   `normalize.PARSERS` if needed. Set `boost > 0` to include the column in full-text search.
2. For a sidebar filter, add its key to `FACETS`.
3. Add `facet_<key>` to **both** `site/i18n/de.yaml` and `site/i18n/en.yaml`.
4. Add display labels to `oercat/vocab/labels.yaml` if the raw values aren't readable as-is.
5. Show the field on the detail page in `site/layouts/oer/page.html` if it should appear there.

`search.js` reads facets, labels and search fields from the `#oer-config` JSON block that
`home.html` renders, so a new facet normally needs no JavaScript change.

### Site (Hugo)
- Hugo ≥ 0.167 is required. Detail pages come from the content adapter
  `site/content-shared/oer/_content.gotmpl`, which is mounted for all languages through
  `module.mounts.sites.matrix`. Don't generate Markdown content files.
- Every UI string goes through `i18n` and must exist in both language files.
- Keep links language- and base-URL-aware (`relLangURL`, `relURL`). The site is deployed under a
  GitHub Pages sub-path.
- CSS: design tokens are at the top of `site/assets/css/main.css`. Reuse them instead of
  hard-coding colours.

### JavaScript
- `site/assets/js/search.js` is one plain ES module: no npm, no build step, no framework.
- Filter state lives in the URL query string (`?q=…&type=Tutorial`). Keep every view shareable.
- `site/assets/js/vendor/minisearch.js` is vendored MiniSearch 7.2.0 (MIT). Don't modify it.

## Tests

- `tests/conftest.py` builds a small workbook in code (`make_workbook`) with good rows and
  deliberately broken ones (a shifted row, a duplicate `No`, a missing title). Extend these
  fixtures rather than adding binary xlsx files.
- Add parser tests to `tests/test_normalize.py`, row/report tests to `tests/test_validate.py`,
  and JSON output tests to `tests/test_export.py`.

## Deployment

`.github/workflows/deploy.yml` deploys to GitHub Pages on every push to `main` that touches
`data/`, `site/`, `oercat/`, `pyproject.toml`, or the workflow. It runs `pip install .` and then
`oercat build --base-url <pages base url>/`. CI doesn't run tests or lint, so run them locally.
Pushing to `main` publishes the site, so don't push without the user's go-ahead.
